# georef_plans.py + tif2mbtiles.py + mbtiles2tif.py — привязка сканов планов, MBTiles и обратно в GeoTIFF

- **georef_plans.py** — автоматически привязывает сканы планов (топосъёмка, план благоустройства и озеленения,
  обычно М 1:500, Беларусь) к Web Mercator (EPSG:3857) по контурам зданий и ортофото НКА. На выходе GeoTIFF,
  **а затем сразу MBTiles** для каждого листа — в той же СК, **на белом фоне** (бумага скана — чисто белая).
- **tif2mbtiles.py** — MBTiles из любых привязанных растров: по одному файлу, списком, папкой или архивом
  (zip/7z/rar/tar). Вызывается из georef_plans.py автоматически, работает и отдельно.
- **mbtiles2tif.py** (v20) — обратно: растровые MBTiles → **GeoTIFF + .tfw/.tfwx + .prj** в нужной СК
  (EPSG:3857 без перепроецирования, EPSG:4326, UTM, СК-42/СК-63 и любая EPSG/PROJ/WKT).
- **mbtiles_shift.py** (v20.7) — ручной сдвиг: MBTiles целиком (все уровни) и привязка готового GeoTIFF.

## Установка

Python 3.9+. Все скрипты должны лежать в одной папке.

```
pip install -r requirements.txt
```

Для архивов .7z и .rar нужен 7-Zip (`7z` в PATH или установленный в `C:\Program Files\7-Zip`); для .7z можно
вместо него поставить `pip install py7zr`. Архивы zip и tar открываются без дополнительных программ.

## 1. Привязка: georef_plans.py

```
python georef_plans.py Avg_001.jpg Avg_002.jpg --address "Минск, проспект Независимости 131" -o out
```

Несколько листов одного объекта лучше передавать вместе: перекрывающиеся листы сшиваются между собой
и привязываются совместно. Вместо адреса можно задать центр: `--center 53.9332,27.6442`.
Без адреса и центра скрипт пробует прочитать адрес со штампа (нужен pytesseract).

Нужен интернет: геокодер Nominatim, тайлы НКА (здания, дороги, ортофото), при необходимости Overpass/Esri.
Скачанные тайлы сохраняются в кэш (`--cache`), повторные запуски идут без сети.

Время: ~1,5 мин на два листа 2331×3240 (без загрузки тайлов) + ~8 с на MBTiles для каждого листа.

### Выходные файлы (папка `-o`)

| файл | что это |
|---|---|
| `<лист>.tif` | GeoTIFF EPSG:3857, RGB, LZW, тайлы 256; скан повёрнут на 0/90/180/270° — «север вверх» |
| `<лист>.tif.ovr` | обзоры (пирамида) для быстрого просмотра |
| `<лист>.tfwx` | world file (A D B E C F) |
| `<лист>.tif.aux.xml` | описание СК для ArcGIS/QGIS |
| `<лист>.mbtiles` | **MBTiles** листа: тайлы EPSG:3857 (та же СК, что у TIF), PNG, **белый фон**, z15–21 (см. раздел 2) |
| `qa_overlay.jpg` | контроль: линии листов (свой цвет у каждого листа) поверх ортофото, контуры зданий НКА — жёлтым |
| `report.txt`, `report.json` | отчёт: сетка, грубая привязка, связи листов, точность, матрицы, углы листов в WGS84, MBTiles |
| `debug_*` | при `--debug`: рабочая область листа, кандидаты грубого поиска |

### Параметры MBTiles в georef_plans.py

| параметр | что делает |
|---|---|
| `--no-mbtiles` | не создавать MBTiles |
| `--mbtiles-format png\|png8\|jpg\|webp` | формат тайлов (по умолчанию png — без потерь) |
| `--mbtiles-zoom 15-21` | уровни вручную (`20` — только максимальный); по умолчанию — по разрешению скана |
| `--mbtiles-background white\|none\|#RRGGBB` | фон: по умолчанию **белый** — тайлы непрозрачные, вне листа белое; `none` — прозрачно вне листа |
| `--mbtiles-paper auto\|clean\|original\|transparent` | бумага скана: `clean` — чисто белая (серый тон, тени, пятна, сгибы убираются; линии, подписи, печати — как в скане), `original` — как в скане, `transparent` — прозрачная; `auto` (по умолчанию) — `clean` для чертежей на светлой бумаге |
| `--mbtiles-white` | только линии на прозрачном: `--mbtiles-paper transparent --mbtiles-background none` (для наложения на подложку) |
| `--mbtiles-merge Объект` | все листы в один `Объект.mbtiles` вместо файла на лист |

### Как работает

1. **Скан**: линии плана, рамка, текстовые блоки (легенда, штамп) исключаются; пунктир (границы газонов и дорожек)
   выделяется отдельно; кресты координатной сетки (шаг 10 см) дают масштаб скана с учётом усадки бумаги.
   **v20.1:** шаг сетки определяется по самим крестам — если лист PDF увеличен или уменьшен при печати/сохранении
   (например, оригинал A2 выведен на A1: кресты через 141,4 мм вместо 100 мм, ×1,414), это распознаётся, в отчёт
   пишется предупреждение, а масштаб берётся по сетке. **Масштаб плана** (`--scale auto`): подпись «М 1:500» в тексте
   PDF (`<скан>.hints.json` рядом со сканом пишет georef_runner), затем OCR штампа (если установлен tesseract),
   иначе 1:500. **Север**: буквы N/S (С/Ю) у стрелки севера задают ориентацию 0/90/180/270°.
2. **Грубый поиск** по контурам зданий НКА: ориентация 0/90/180/270°, поворот ±6°, масштаб ±2%,
   корреляция + ICP + совпадение «коридоров» плана с осями дорог. Точность ~3–5 м.
   **v20.1:** кандидат принимается, только если лист **целиком внутри круга поиска** и **захватывает адрес**
   (для улицы — хотя бы один её участок из OSM). Если сетки нет и совпадений мало, пробуется поправка листа
   ×√2 / ×1/√2 (A2 ↔ A1 и т. п.; отключается `--no-paper`).
3. **Связь листов**: поиск поворота/сдвига по общей части и affine-ICP по всей «туши» (точность ~0,1 м).
4. **Тонкая привязка по ортофото** (z20, ~9 см/px): точки линий всех листов делятся на классы — пунктир,
   сплошные вне зданий (бордюры, проезды, дорожки), у зданий (малый вес: на ортофото крыши высоток смещены);
   перебор поворота ±2,5° и сдвига ±8 м по направленным градиентам ортофото → уточнение лучших пиков →
   профили «точка — кромка» (робастный МНК). Модель `rigid`: масштаб по сетке, по ортофото только поворот и сдвиг
   (с учётом разного масштаба WM по востоку и северу). Без сетки — `similarity` (масштаб по ортофото).
5. **Экспорт** GeoTIFF и отчёт.
6. **MBTiles** из готовых GeoTIFF через tif2mbtiles.py — без перепроецирования (GeoTIFF уже в EPSG:3857).

### Основные параметры привязки

- `--address` / `--center lat,lon` — где искать; `--radius auto|м` (v20.1, по умолчанию `auto`): охват адреса
  (для улицы — все её участки в OSM, для дома — дом, для точки — ±100 м) + половина диагонали листа + 25 м;
  заданный радиус меньше половины диагонали листа увеличивается (лист должен помещаться в круг);
  `--area area.json` — охват, найденный заранее (так делает georef_runner по адресу из интерфейса);
- `--scale auto|500` (v20.1, по умолчанию `auto` — из текста PDF/штампа, иначе 1:500), `--dpi` (если в файле нет
  или неверно), `--orient 90` — если поиск путается;
- `--model auto|rigid|similarity|affine`, `--no-grid` (не использовать сетку), `--no-fine` (только грубая привязка);
- `--w-dotted`, `--w-solid`, `--w-near`, `--bld-buffer` — веса классов линий и буфер «у зданий»;
- `--search-angle`, `--search-shift` — диапазон перебора тонкой привязки;
- `--buildings osm`, `--ortho esri` — другие эталоны; `--cache` — папка кэша; `--debug`.

Полный список: `python georef_plans.py -h`.

### Как проверить результат

Откройте `qa_overlay.jpg` или загрузите `.tif`/`.mbtiles` в QGIS поверх ортофото (например, XYZ-слой НКА или Esri).
В `report.txt` для каждого класса линий указана доля точек, у которых на ортофото найдена кромка в пределах ±0,3 м,
и «согласованность» — насколько сдвинулся бы результат при подгонке только по одному классу.

### Ограничения привязки

- Ключи доступа к тайлам НКА взяты из публичного веб-клиента map.nca.by и могут смениться —
  тогда используйте `--buildings osm --ortho esri` (точность Esri хуже).
- Контуры зданий НКА и ортофото — по крышам. У высоких домов крыша смещена относительно фундамента
  на несколько метров, поэтому здания служат только для грубого поиска.
- Содержимое плана может расходиться с построенным. На тестовых листах пунктир (дорожки, газоны) и сплошные линии
  (бордюры, проезды) согласуются с ортофото с разницей ~1–2 м; итог ближе к проездам и бордюрам — топооснове плана.
- Локальные искажения бумаги (сгибы, коробление) не моделируются: на лист — одно жёсткое/подобное преобразование,
  между листами — affine.
- При повторяющейся застройке грубый поиск может ошибиться — задайте `--center`, уменьшите `--radius`,
  укажите `--orient`; результат всегда проверяйте по `qa_overlay.jpg`.
- Масштаб в `report.txt` «на листе файла 1:353» при масштабе плана 1:500 — не ошибка: лист PDF увеличен ×1,414;
  GeoTIFF строится по фактическому размеру пикселя (по сетке и ортофото).

## 2. MBTiles: tif2mbtiles.py

```
python tif2mbtiles.py out\Avg_001.tif out\Avg_002.tif     # Avg_001.mbtiles и Avg_002.mbtiles рядом с TIF
python tif2mbtiles.py планы.zip -o mbtiles                 # все привязанные растры из архива
python tif2mbtiles.py D:\Планы -o mbtiles                  # папка целиком (с подпапками и архивами внутри)
python tif2mbtiles.py *.tif --merge Объект_131             # все растры в один Объект_131.mbtiles
python tif2mbtiles.py скан.jpg --src-crs EPSG:32635        # JPG + .jgw без .prj, координаты в UTM 35N
python tif2mbtiles.py Пар-2-73.tif                         # .tfw без .prj: СК по координатам (СК-42 зона 5 -> EPSG:28405)
python tif2mbtiles.py лист.tif --shift 2.5,-1.2            # сдвинуть результат на 2,5 м восток / 1,2 м юг (м EPSG:3857)
```

### Что принимает

- **GeoTIFF** со встроенной привязкой (результат georef_plans.py, QGIS, ArcGIS, Global Mapper и т. п.).
- **Растр + world-файл**: TIF/JPG/PNG/BMP/GIF с `.tfw`/`.tfwx`/`.tifw`, `.jgw`/`.jgwx`/`.jpgw`, `.pgw`/`.pgwx`/`.pngw`,
  `.bpw`, `.wld`; СК — из `.prj` или `.aux.xml` рядом.
- Всё, что читает GDAL с привязкой: MapInfo `.tab`, GCP, JPEG 2000, ERDAS IMG, VRT, RSW («Панорама»).
- Палитра и 1-бит (в т. ч. CCITT G4) → серый/RGB; 16 бит и float → 8 бит (растяжка 2–98%);
  альфа-канал и nodata → прозрачность.
- **Архивы**: zip (в т. ч. с кириллическими именами из «Проводника» Windows), 7z, rar, tar, tar.gz/tgz, tar.bz2, tar.xz;
  папки и архивы внутри архива. World-файлы и `.prj` должны лежать в архиве рядом со своим растром.
- Файлы без привязки (`readme.png`, `qa_overlay.jpg`) пропускаются с предупреждением, остальные обрабатываются.

### Система координат

Формат MBTiles допускает только **Web Mercator (EPSG:3857)** — сетку тайлов XYZ (Google/OSM), иначе приложения
файл не покажут. GeoTIFF из georef_plans.py уже в EPSG:3857, поэтому тайлы режутся **в той же СК, без
перепроецирования** — только пересчёт на сетку тайлов (тайлы максимального уровня совпадают с прямым пересчётом TIF
до пикселя). Растры в других СК (UTM, СК-42/СК-63 с `.prj`, WGS84 и т. д.) перепроецируются в EPSG:3857
автоматически; проверка на копиях листа в UTM 35N и WGS84 — расхождение с исходным ≤ 0,05 px (~2 мм).

Порядок поиска СК: в самом файле (GeoTIFF / `.aux.xml`) → `.prj` → `.aux.xml` → координаты в градусах = EPSG:4326 →
`--src-crs` (по умолчанию `auto`). `--force-crs EPSG:xxxx` — назначить СК принудительно.

**[v20.3] `--src-crs auto`** (по умолчанию; `EPSG:3857` прежних версий — тоже авто): если в файле СК нет, перебираются
Web Mercator, СК-42 6°/3° с номером зоны в X (EPSG:284xx, 2523–2529), без номера зоны — UTM, СК-42 6° (2494–2496)
и 3° (2582–2586); подходит СК, в которой все углы растра в Беларуси (`GEOREF_REGION_BBOX`, `off` — без проверки).
Одна подходящая — принимается с предупреждением; несколько — растр пропускается, в журнале список «(EPSG:N); …»
(задайте `--src-crs` явно); ни одной — ошибка «вероятно, местная СК». Растр с СК, но вне региона — предупреждение.
`--shift DX,DY` — сдвиг результата (м EPSG:3857), `--only ПОДПИСЬ` — только выбранные растры, `--result-json FILE`.
Для местных систем (МСК) без `.prj` и без EPSG-кода тайлы построить нельзя: нужна СК с параметрами.

### Фон и бумага

- По умолчанию **белый фон**: все тайлы непрозрачные (RGB, без альфа-канала), вне растра и на участках «нет данных» —
  белое, тайлы идут сплошным прямоугольником по охвату листа, без дыр. Другой цвет — `--background black|#RRGGBB|R,G,B`;
  `--background none` — прозрачный фон, как в прошлой версии (для наложения на подложку; jpg — всегда на белом).
- **Бумага скана** (`--paper`, по умолчанию `auto`):
  - `clean` — бумага чисто белая: серый тон скана, тени, пятна, сгибы выравниваются локально, линии, подписи,
    штампы и печати остаются в цветах скана; файл PNG при этом в ~4 раза меньше;
  - `original` — как в растре;
  - `transparent` — бумага прозрачная, видны только линии (по умолчанию вместе с прозрачным фоном);
  - `auto` — `clean` для чертежей на светлой бумаге, `original` для остального (ортофото, тёмный фон).
  Порог бумаги — `--white-threshold 235`. `--white-transparent` = `--paper transparent --background none`.
- `--merge` с белой бумагой: следующий лист закрывает предыдущий в зоне перекрытия; чтобы на белом были видны линии
  всех листов — `--paper transparent --background white`.

### Уровни и форматы

- Максимальный уровень — не грубее разрешения растра (для листов 1:500 при 200 dpi — z21, ~7 см/px),
  минимальный — когда весь лист занимает ~полтайла (z15). Нижние уровни — усреднением 2×2 с учётом прозрачности.
  Вручную: `--minzoom`, `--maxzoom`; `--maxzoom 20` уменьшает файл в ~3–4 раза.
- `--format png` (по умолчанию) — без потерь; `png8` — 256 цветов; `jpg` (`--quality 85`); `webp` — самый компактный,
  но поддерживается не всеми приложениями. Лист 3240×2331 px, z15–21, 421 тайл:

  | формат | белый фон, бумага `clean` (по умолчанию) | бумага `original` |
  |---|---|---|
  | png | **4,4 МБ** | 17 МБ |
  | png8 | 1,4 МБ | 4,4 МБ |
  | jpg | 1,9 МБ | 3,4 МБ |
  | webp | 0,9 МБ | 1,8 МБ |

- `--merge NAME` — все растры в один файл (следующие поверх предыдущих); `--name` — название слоя;
  `--resampling cubic|bilinear|lanczos|nearest…`; `--src-nodata 0|255`; `--tile-size 512`.

Полный список: `python tif2mbtiles.py -h`.

### Где открыть

QGIS и всё на GDAL (перетащить файл в окно), мобильные приложения с поддержкой растровых MBTiles (Locus Map,
Guru Maps и др.), веб-карты через tileserver-gl / MapLibre. Внутри — стандарт MBTiles 1.3: таблицы `metadata`
и `tiles` (ряды TMS), в metadata — name, format, bounds, center, minzoom, maxzoom, type (`baselayer` при белом
фоне, `overlay` при прозрачном) и description с исходными файлами, их СК и фоном.

## 3. MBTiles → GeoTIFF: mbtiles2tif.py (v20)

```
python mbtiles2tif.py plan.mbtiles                         # plan.tif + plan.tfw + plan.tfwx + plan.prj рядом
python mbtiles2tif.py a.mbtiles b.mbtiles -o tif           # несколько файлов в папку tif\
python mbtiles2tif.py plan.mbtiles --crs EPSG:32635        # в UTM 35N (перепроецирование GDAL)
python mbtiles2tif.py plan.mbtiles --zoom 18 --background white --compress jpeg
```

На выходе для каждого MBTiles: `<имя>.tif` (СК записана и внутри файла, внутренние пирамиды),
`<имя>.tfw` и `<имя>.tfwx` (world-файл: A, D, B, E, C, F; C/F — центр левого верхнего пикселя; .tfwx — то же
содержимое для программ, которые ищут это расширение), `<имя>.prj` (ESRI WKT) и `<имя>_preview.png` (просмотр).

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--zoom` | `max` | Уровень тайлов: `max` — самый подробный, `auto` — самый подробный в пределах `--max-mp`, или номер уровня. |
| `--crs` | `EPSG:3857` | СК результата: `EPSG:XXXX`, PROJ-строка или WKT. 3857 — пиксель в пиксель с тайлами, без потерь. |
| `--compress` | `deflate` | `deflate`, `lzw`, `jpeg` (меньше, с потерями; прозрачность — маской) или `none`. |
| `--background` | `none` | `none` — прозрачность альфа-каналом; `white`, `black`, `#RRGGBB` — заливка пустых мест. |
| `--clip` | `auto` | `auto` — обрезать пустые поля по краям, `bounds` — по границам из metadata, `none` — все тайлы целиком. |
| `--max-mp` | `400` | Предел размера результата, Мпикс (или `GEOREF_MB2TIF_MAX_MP`). При превышении берётся уровень мельче — с предупреждением. |
| `--resampling` | `cubic` | Пересчёт при смене СК: `nearest`, `bilinear`, `cubic`, `lanczos`, `average`. |
| `--no-overviews`, `--threads` | | Без пирамид; число потоков чтения тайлов. |

Принимаются растровые MBTiles (PNG/JPEG/WebP) со схемой TMS (по спецификации) или XYZ (`scheme=xyz` в metadata).
Векторные MBTiles (pbf) и файлы без тайлов отклоняются с понятной ошибкой. В портале то же самое — «Конвертер СК» →
вкладка «MBTiles → TIFF» (результаты — ZIP, просмотр на карте).

`--shift DX,DY` (v20.7) — сдвинуть результат на DX м на восток и DY м на север (метры EPSG:3857): привязка
GeoTIFF/TFW/TFWX и границы сдвигаются точно, пиксели те же. `--name` — имя результата, `--result-json` — сведения в JSON.

## 4. Ручной сдвиг: mbtiles_shift.py (v20.7)

```
python mbtiles_shift.py tiles plan.mbtiles -o plan_сдвиг.mbtiles --shift 12.5,-7.25   # MBTiles целиком, все уровни
python mbtiles_shift.py delta plan_utm.tif --shift 12.5,-7.25                         # сдвиг привязки в СК файла (JSON)
```

* `tiles` — каждый уровень сдвигается на `round(сдвиг / размер пикселя уровня)` пикселей: тайлы пересобираются
  кусками по 96, схема TMS/XYZ и формат сохраняются, края — прозрачные (PNG/WebP) или белые (JPEG), пустые тайлы
  не пишутся; уровни, где сдвиг меньше половины пикселя, копируются байт в байт. `bounds`/`center` сдвигаются,
  в metadata — `georef_shift_3857`. Предел — `--max-tiles` (или `GEOREF_SHIFT_MAX_TILES`, 250000). Векторные — отказ.
* `delta` — сдвиг привязки GeoTIFF в его СК и ошибка на углах (`err_px`): если ≤ 0,2 пикселя, портал сдвигает
  привязку на месте, иначе собирает GeoTIFF из MBTiles заново со сдвигом.
