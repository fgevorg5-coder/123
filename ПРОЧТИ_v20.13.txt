ГЕОСЕРВИС v20.13 — УСТОЙЧИВОСТЬ ПОД НАГРУЗКОЙ 100+ ПОЛЬЗОВАТЕЛЕЙ

ЧТО ИЗМЕНИЛОСЬ
Исправлены ошибки, из-за которых при одновременной работе многих пользователей
сервис «лагал» и останавливался:
- зависание всего сервиса при одновременных запросах контура страны
  (/api/country-boundary) после запуска;
- запросы к базе данных, Redis, SQLite и файлам выполнялись в главном потоке
  сервера и задерживали всех остальных пользователей — переведены в пул потоков;
- при ~85 и более пользователях сервер отвечал 503 даже на страницу карты, а
  затем 403 на все тайлы (лимит соединений uvicorn в server.py);
- каждый непрогретый тайл снимков шёл отдельным запросом в PostGIS — теперь контуры
  снимков держатся в памяти, пустые тайлы запоминаются, одинаковые запросы склеиваются;
- ошибки GeoServer кэшировались браузером и nginx на сутки; пустые тайлы — на неделю;
- поиск адресов шёл в Nominatim без кэша (риск бана IP для всех пользователей);
- очистка кэша nginx на Windows ничего не удаляла, но сообщала об успехе.
Подробности и измерения — reports/v20.13_load_report.md, CHANGELOG_RU.md.

УСТАНОВКА
1. Остановите геосервис и сохраните резервную копию каталога проекта.
2. Скопируйте содержимое папки geoservice из архива поверх папки проекта с заменой.
   Изменённые файлы: app.py, server.py, security_hardening.py, jobkit.py,
   lesolidar_bridge.py, georef_api.py, manuals_editor_api.py, geo_guard.py.
   Новый файл: perf_kit.py (обязателен — app.py его импортирует).
3. Запустите сервис через server.py (один процесс, как раньше). Браузер: Ctrl+F5.
4. Проверка: python tests/perf_kit/test_perf_kit.py — «все проверки пройдены».

НОВЫЕ ПЕРЕМЕННЫЕ .env (все необязательные, значения по умолчанию в скобках)
  GEOSERVER_BASE_URL     (http://192.168.12.109:9090/geoserver) — адрес внутреннего GeoServer
  OPEN_METEO_URL         (https://api.open-meteo.com/v1/forecast)
  DB_POOL_SIZE / DB_MAX_OVERFLOW / DB_POOL_TIMEOUT   (10 / 10 / 30) — пул PostgreSQL;
                         сумма pool_size+max_overflow должна быть меньше max_connections
  UVICORN_LIMIT_CONCURRENCY (4096), UVICORN_MAX_REQUESTS (0 = не перезапускать процесс)
  WMS_MAX_SIDE           (1024) — максимальный WIDTH/HEIGHT запроса GetMap
  VISIT_WRITE_INTERVAL   (60) — секунд между записями визита одного IP
  GEOCODE_CACHE_TTL / GEOCODE_CACHE_MAX / NOMINATIM_MIN_INTERVAL   (600 / 5000 / 1.0)
  WEATHER_CACHE_MAX      (5000)
  RASTER_EMPTY_CACHE_TTL / RASTER_EMPTY_CACHE_MAX / IMAGERY_INDEX_TTL   (600 / 200000 / 300)
  RATE_LIMIT_WORKERS     (1) — делитель лимитов, если воркеров больше одного
  LESOLIDAR_MAX_QUEUE    (12), GEOREF_MAX_PER_IP (4)

НАГРУЗОЧНАЯ ПРОВЕРКА НА СВОЁМ СЕРВЕРЕ
  pip install httpx
  python tests/load/load_test.py --url http://<адрес сервиса> --users 100 --duration 120
Вердикт PASS при p95 ≤ 1,5 с и ошибках ≤ 1 %. Запускайте в согласованное окно.
Локальный стенд с моком GeoServer — tests/load/README_RU.md.

ОГРАНИЧЕНИЯ
- Сервис по-прежнему работает одним процессом: ~1000–1250 запросов/с на процесс.
  Для перехода на несколько воркеров нужно вынести одноразовые токены скачивания,
  подписчиков SSE и лимитеры в Redis — см. «Что дальше» в отчёте.
- Стенд проверял серверную часть на синтетических данных; GeoServer и PostGIS
  рабочего сервера могут быть медленнее мока.
